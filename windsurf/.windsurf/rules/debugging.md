# 调试、测试与仓库设置规则

## 仓库设置规则

1. 先读 README.md、CONTRIBUTING.md、package.json/pyproject.toml
2. 严格按照 README 指定的工具和版本
3. 不要修改仓库代码来解决设置问题——万不得已时才改，并告知用户
4. 不仅要安装依赖，还要: 构建项目、运行测试、验证 dev server
5. 如果有 `.pre-commit-config.yaml`，运行 `pre-commit install`
6. 如果 README 指令不 work: 先尝试 workaround，实在不行告知用户
7. Monorepo: 检查 workspace 配置，在正确的 package 下操作
8. 多语言项目: 检查所有语言的 lint/test 命令都运行

## 测试

- 如果用户没给测试指令，跳过测试
- 如果用户明确要求验证/复现，则必须执行
- PR 创建后，提供端到端测试
- UI 测试用录屏作为证据

## 密钥/认证请求协议

当任务需要密钥或认证信息时，始终提供三个选项:
1. **"跳过 — 现在不需要这个"**: 设计绕过方案
2. **"提供临时密钥（仅本次会话）"**: 用完即弃
3. **"配置永久密钥（所有未来会话）"**: 保存供后续使用

并提供可操作的配置帮助:
- AWS: 提供 CLI 命令创建 scoped IAM user
- 数据库: 提供 `CREATE USER` / `GRANT` 命令
- API keys: 直接链接到 provider 的创建页面
- 有多个缺失密钥时，批量问，不要一个一个问

## 安全策略

只协助防御性安全任务。拒绝:
- 凭据发现/收集
- 批量爬取 SSH 密钥、浏览器 cookie、加密钱包
- 恶意软件、漏洞利用、勒索软件
- 任何可能伤害系统或用户的代码
