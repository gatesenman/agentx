# 子会话管理工作流

## 适用场景
```
适合:
  ✓ 并行独立任务（多个 bug 修复、多个功能）
  ✓ 批量处理（多仓库操作）
  ✓ 分治策略（大任务拆分为子任务）

不适合:
  ✗ 有依赖的任务（A 的输出是 B 的输入）
  ✗ 修改同一文件的任务
  ✗ 需要共享状态的任务
  ✗ 子会话运行在独立 VM，不共享文件系统
```

## 步骤

### 1. 分析和拆分
```
将大任务拆分为独立子任务:
  - 每个子任务有清晰的输入和输出
  - 子任务之间无依赖
  - 每个子任务可独立验证
```

### 2. 创建子会话
```
通过 devin_mcp 调用 devin_session_create:
  - prompt: 详细描述子任务
  - 包含仓库信息
  - 包含验收标准

每个子任务一个会话
```

### 3. 监控进度
```
通过 devin_mcp 调用:
  - devin_session_events: 检查特定会话事件
  - devin_session_gather: 等待多个会话完成
```

### 4. 检查结果
```
每个子会话完成后:
  1. 检查是否成功完成
  2. 检查创建的 PR（如有）
  3. 检查输出内容
  4. 记录结果
```

### 5. 汇总报告
```
汇总所有子会话结果:
  - 成功的任务
  - 失败的任务（含原因）
  - 创建的 PR 列表
  - 发现的问题

发送给用户
```

## 子会话提示词编写
```
必须包含:
  1. 清晰的任务描述
  2. 仓库路径
  3. 具体的操作步骤
  4. 验收标准
  5. 约束条件（不要改什么）

示例:
  "在 owner/repo 仓库中:
   1. 找到 src/utils.ts 中的 calculateTotal 函数
   2. 修复当输入为空数组时返回 NaN 的 bug
   3. 添加空数组检查，返回 0
   4. 确保现有测试通过
   5. 创建 PR"
```
