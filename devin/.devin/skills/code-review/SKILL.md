# 代码审查响应工作流

## 步骤

### 1. 阅读反馈
```
查看 PR 评论:
  - 调用 git_view_pr 获取所有评论
  - 逐条阅读审查反馈
  - 记录每条需要处理的反馈
```

### 2. 分类反馈
```
每条反馈分类:
  A. 代码变更请求 → 修改代码
  B. 问题/澄清 → 回复解释
  C. 建议 → 评估并决定是否采纳
  D. 指出 bug → 立即修复
```

### 3. 逐条处理
```
对每条反馈:
  1. 阅读指出的代码
  2. 理解反馈的要求
  3. 实现修改（如需要）
  4. 运行测试验证
  5. 提交
  6. 回复评论
```

### 4. 验证
```bash
# 每次修改后
npm run lint
npm run typecheck
npm test
```

### 5. 提交和推送
```bash
# 每条反馈单独提交
git add src/修改的文件.ts
git commit -m "fix: 回应审查反馈 - 具体描述"

# 全部完成后推送
git push
```

### 6. 回复评论
```
对每条反馈:
  - 调用 git_comment_on_pr(in_reply_to=评论ID)
  - 说明做了什么修改
  - 或解释为什么没改
```

## 原则
- 每条反馈都要回应（修改或解释）
- 代码变更要验证（lint + test）
- 不要一次性 force push（只添加新提交）
- 如有分歧，礼貌地解释理由
