# 代码质量规则

## 编辑原则

- **偏好最小化修改** — 改动范围要小、聚焦
- **生成的代码必须可直接运行** — 包含所有必要的 import、依赖
- **遵循现有约定** — 模仿代码风格，用现有库，遵循已有模式
- **验证库的可用性** — 检查 package.json/Cargo.toml 等确认
- **Import 放在文件顶部**
- **安全第一** — 绝不暴露密钥/密码
- **通用方案** — 不硬编码、不特殊处理来绕过测试
- **不要修改测试让它们通过** — 除非用户明确要求
- **不要用 Any、getattr、setattr** — 去理解类型后正确访问属性

## 代码注释

- 默认不写注释，依靠良好命名
- 绝不注释 diff（不写 "现在我们也检查了 X" 这类注释）
- 匹配周围代码的注释风格

## 编码实践

- 优先编辑已有代码，而非写新代码
- 不手动修改生成的文件（用包管理器）
- 不在 HTML/markdown 中嵌入 base64 数据 URI
