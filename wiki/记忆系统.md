# 记忆系统

AgentX 的记忆系统采用 7 层架构，从短期到长期，从易失到持久，确保 AI 智能体在多会话间保持上下文连贯性。

---

## 7 层记忆架构

```
┌─────────────────────────────────────┐
│  第 7 层: 浏览器配置文件             │  ← 持久化 Cookie/登录态/存储
│  Browser Profiles                   │
├─────────────────────────────────────┤
│  第 6 层: 密钥管理                   │  ← 加密存储、自动注入
│  Secrets Management                 │
├─────────────────────────────────────┤
│  第 5 层: 环境蓝图                   │  ← VM 快照、环境配置
│  Environment Blueprints             │
├─────────────────────────────────────┤
│  第 4 层: Playbook 工作流            │  ← 可复用的任务模板
│  Playbooks                          │
├─────────────────────────────────────┤
│  第 3 层: 技能文件                   │  ← 仓库级别的操作指南
│  Skills (.devin/skills/)            │
├─────────────────────────────────────┤
│  第 2 层: 知识库                     │  ← 跨会话的结构化知识
│  Knowledge Notes                    │
├─────────────────────────────────────┤
│  第 1 层: 会话上下文                 │  ← 当前会话的对话和操作
│  Session Context                    │
└─────────────────────────────────────┘
```

---

## 各层详解

### 第 1 层: 会话上下文

**生命周期**: 单次会话  
**存储位置**: 内存  
**管理方式**: 自动

- 包含当前对话历史、文件操作记录、命令执行结果
- 会话结束时自动生成摘要（summarization）
- 长时间运行的会话会自动裁剪上下文
- 关键信息（TODO 列表、重要发现）会在摘要中保留

**对应工具**: `todo_write`（管理任务列表，会话间可见）

### 第 2 层: 知识库

**生命周期**: 跨会话持久  
**存储位置**: Devin 平台数据库  
**管理方式**: 手动创建 / 自动建议

```
知识笔记结构:
├── id: note-xxx（唯一标识）
├── name: "Lint 前必须运行"（标题）
├── trigger: "当修改代码准备提交时"（触发条件/范围）
├── body: "在此仓库中提交前必须运行 npm run lint"（内容）
├── author: "user" 或 "system"
└── scope: 何时自动注入
```

**对应工具**:
| 工具 | 作用 |
|------|------|
| `list_knowledge_notes` | 列出所有知识笔记 |
| `get_knowledge_note` | 获取笔记完整内容 |
| `suggest_knowledge` | 建议创建/更新知识 |

**自动注入机制**: 相关知识会在会话开始时和上下文匹配时自动注入为 `<knowledge>` 标签。

### 第 3 层: 技能文件

**生命周期**: 跟随仓库代码  
**存储位置**: 仓库 `.devin/skills/` 目录  
**管理方式**: 通过 `suggest_skill_pr` 创建 PR

```
技能文件结构:
.devin/skills/
├── testing/
│   └── SKILL.md      # YAML frontmatter (name, description) + Markdown
├── pr-workflow/
│   └── SKILL.md
├── debugging/
│   └── SKILL.md
└── ...
```

**激活方式**: 按需激活，AI 根据任务类型决定是否使用  
**关键规则**:
- 激活后成为首要指令来源
- 必须按步骤顺序执行
- 不能跳步或替换步骤

### 第 4 层: Playbook 工作流

**生命周期**: 组织级别持久  
**存储位置**: Devin 平台  
**管理方式**: 通过 Devin MCP API 管理

Playbook 是预定义的任务模板，比技能更结构化：

```
Playbook 属性:
├── name: "Bug 修复流程"
├── trigger: 任务类型匹配时自动建议
├── steps: 具体步骤列表
└── variables: 可配置参数
```

### 第 5 层: 环境蓝图

**生命周期**: 组织/仓库级别持久  
**存储位置**: Devin 平台配置  
**管理方式**: `read_environment_config` / `update_environment_config`

```yaml
# environment.yaml 蓝图结构
initialize: |
  # 首次构建快照时运行（安装工具、全局依赖）
  curl -LsSf https://astral.sh/uv/install.sh | sh

maintenance: |
  # 每次快照更新时运行（增量更新依赖）
  npm install
  pip install -r requirements.txt

knowledge:
  - name: lint
    contents: npm run lint
  - name: test
    contents: npm test
  - name: startup
    contents: npm run dev
```

**分层**: 组织级蓝图 → 仓库级蓝图（仓库级覆盖组织级）

### 第 6 层: 密钥管理

**生命周期**: 按作用域持久  
**存储位置**: 加密存储  
**管理方式**: `request_secret` / `suggest_save_secret`

```
密钥作用域:
├── org: 组织全局（所有会话可用）
├── user: 个人专属（仅用户自己的会话）
└── repo: 仓库专属（仅特定仓库的会话）
```

**自动注入**: 密钥以环境变量形式自动注入到 Shell 环境

### 第 7 层: 浏览器配置文件

**生命周期**: 跨会话持久  
**存储位置**: 压缩存档  
**管理方式**: `save_browser_profile`

- 保存 Cookie、本地存储、密码等
- 下次会话自动恢复登录状态
- 避免重复登录

## 知识生命周期

```
新会话开始
    │
    ▼
系统注入相关知识
    ├─ 匹配当前仓库的知识
    ├─ 匹配当前任务类型的知识
    └─ 用户创建的全局知识
    │
    ▼
会话执行过程
    ├─ 发现可复用的经验 → suggest_knowledge（建议创建知识）
    ├─ 发现已有知识不准确 → suggest_knowledge（建议更新知识）
    └─ 完成重要配置 → suggest_skill_pr（建议创建技能 PR）
    │
    ▼
会话结束
    ├─ 自动生成会话摘要
    └─ 用户审批知识/技能建议
```

## 跨 IDE 记忆适配

不同 IDE 对记忆系统的支持程度不同：

| 记忆层 | Devin | Claude Code | Cursor | 其他 IDE |
|--------|-------|-------------|--------|---------|
| 会话上下文 | 自动管理 | 自动管理 | 自动管理 | 自动管理 |
| 知识库 | 原生支持 | 通过 CLAUDE.md 模拟 | 通过 .cursorrules 模拟 | 通过规则文件模拟 |
| 技能文件 | 原生支持 | 手动参考文档 | 手动参考文档 | 手动参考文档 |
| Playbook | 原生支持 | 通过工作流文档模拟 | 通过工作流文档模拟 | 通过工作流文档模拟 |
| 环境蓝图 | 原生支持 | 不适用 | 不适用 | 不适用 |
| 密钥管理 | 原生支持 | 环境变量 | 环境变量 | 环境变量 |
| 浏览器配置 | 原生支持 | 不适用 | 不适用 | 不适用 |

**说明**: 非 Devin IDE 通过静态文件（规则文件、工作流文档）来模拟记忆效果。虽然不如 Devin 的动态系统强大，但能在规则层面提供一致的行为引导。

---

## 最佳实践

1. **知识笔记要具体** — "在此仓库提交前运行 `npm run lint`" 优于 "记得跑 lint"
2. **设定精确的触发条件** — 让知识在正确时机注入，避免噪音
3. **定期清理** — 删除过时的知识，保持知识库精简
4. **分层存储** — 全局知识放组织级，仓库知识放仓库级
5. **技能要可执行** — 每个步骤都要有明确的命令或操作
