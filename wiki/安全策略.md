# 安全策略

AgentX 的安全策略覆盖密钥保护、代码安全、提交安全三个层面。

---

## 密钥保护

### 三道防线

```
第一道防线: pre-commit Hook
    → 每次 git commit 自动扫描暂存文件
    → 发现密钥立即阻止提交

第二道防线: verify-no-secrets.sh 脚本
    → 深度扫描整个仓库（10 类密钥）
    → 可集成到 CI 流水线

第三道防线: 智能体规则
    → 规则文件中明确禁止提交密钥
    → AI 在生成代码时避免硬编码密钥
```

### 检测的密钥类型

| # | 类型 | 检测模式 | 风险等级 |
|---|------|---------|---------|
| 1 | AWS Access Key ID | `AKIA[0-9A-Z]{16}` | 高 |
| 2 | AWS Secret Access Key | `aws_secret_access_key` | 高 |
| 3 | GitHub Personal Access Token | `ghp_[a-zA-Z0-9]{36}` | 高 |
| 4 | GitHub OAuth Token | `gho_[a-zA-Z0-9]{36}` | 高 |
| 5 | GitHub Fine-grained PAT | `github_pat_[a-zA-Z0-9_]{82}` | 高 |
| 6 | OpenAI API Key | `sk-[a-zA-Z0-9]{20,}` | 高 |
| 7 | 私钥文件 | `-----BEGIN.*PRIVATE KEY-----` | 极高 |
| 8 | 数据库连接字符串 | `(mysql\|postgres\|mongodb)://.*:.*@` | 高 |
| 9 | JWT Token | `eyJ[a-zA-Z0-9_-]*\.eyJ` | 中 |
| 10 | Slack Token | `xox[bprs]-` | 中 |
| 11 | Google API Key | `AIza[0-9A-Za-z_-]{35}` | 高 |
| 12 | 通用密码赋值 | `password\s*=\s*['"][^'"]+['"]` | 中 |
| 13 | 通用 Token/Secret | `(secret\|token\|api_key)\s*=\s*['"]` | 中 |

### 禁止提交的文件

| 文件类型 | 匹配模式 | 原因 |
|---------|---------|------|
| 环境变量 | `.env`, `.env.*` | 通常包含密钥 |
| SSL 证书 | `*.pem`, `*.key` | 私钥文件 |
| PKCS | `*.p12`, `*.pfx` | 证书包 |
| 服务账号 | `credentials.json`, `service-account.json` | GCP/Firebase 凭证 |
| SSH 密钥 | `id_rsa`, `id_ed25519` | SSH 私钥 |

## 密钥管理最佳实践

### 正确做法

```bash
# 使用环境变量
export DATABASE_URL="postgres://user:pass@host/db"

# 在代码中引用环境变量
import os
db_url = os.environ["DATABASE_URL"]
```

```javascript
// JavaScript/TypeScript
const apiKey = process.env.API_KEY;
```

### 错误做法

```python
# 绝对不要这样做！
API_KEY = "sk-abc123def456"  # ← 会被 pre-commit hook 拦截
DATABASE_URL = "postgres://admin:password123@db.example.com/mydb"  # ← 拦截
```

### 密钥请求三选项协议

当 AI 智能体需要密钥时，必须提供三个选项：

1. **跳过** — 不用密钥继续（设计绕过方案）
2. **临时提供** — 仅本次会话使用（`should_save=false`）
3. **永久保存** — 所有未来会话可用（`should_save=true`）

## 代码安全规则

### 智能体安全边界

AI 智能体被配置为**仅执行防御性安全任务**，拒绝：

| 禁止行为 | 说明 |
|---------|------|
| 密钥收集/发现 | 不扫描系统寻找密钥 |
| 批量爬取 SSH 密钥 | 不搜索浏览器 Cookie、加密钱包 |
| 恶意软件编写 | 不创建/修改/改进恶意代码 |
| 漏洞利用 | 不编写 exploit 代码 |
| 勒索软件 | 不创建任何可能伤害系统或用户的代码 |

### 安全编码规则

1. **永不硬编码密钥** — 所有密钥通过环境变量或密钥管理服务引用
2. **永不日志输出密钥** — 不在 console.log / print 中输出密钥值
3. **永不在 URL 中嵌入 Token** — 使用 `https://github.com/repo.git`，不用 `https://token@github.com/repo.git`
4. **输入验证** — 所有外部输入必须验证和转义
5. **最小权限** — 代码只请求必需的权限

## 提交安全

### Git 规则

| 规则 | 说明 |
|------|------|
| 不 `git add .` | 可能意外添加密钥文件 |
| 不 force push main | 可能覆盖他人工作 |
| 不 `--no-verify` | 绕过安全检查 |
| 不 amend commits | 可能修改已推送的历史 |
| 不提交 `.env` | 环境变量文件不入库 |

### .gitignore 模板

AgentX 提供了预配置的 `.gitignore` 模板（`templates/gitignore.template`），包含：

```gitignore
# 环境变量
.env
.env.local
.env.*.local

# 密钥文件
*.pem
*.key
*.p12
*.pfx
id_rsa
id_ed25519

# 凭证
credentials.json
service-account.json

# IDE 敏感文件
.idea/
.vscode/settings.json

# 依赖目录
node_modules/
.venv/
__pycache__/

# 构建产物
dist/
build/
*.egg-info/
```

## CI 集成

### 在 CI 中运行密钥扫描

```yaml
# GitHub Actions 示例
name: Security Scan
on: [push, pull_request]

jobs:
  secrets-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: 扫描密钥
        run: bash scripts/verify-no-secrets.sh
```

### 推荐的 CI 安全检查

| 工具 | 用途 | 安装 |
|------|------|------|
| `verify-no-secrets.sh` | AgentX 自带密钥扫描 | 已包含 |
| `gitleaks` | 更全面的密钥检测 | `brew install gitleaks` |
| `trivy` | 依赖漏洞扫描 | `brew install trivy` |
| `semgrep` | 静态代码安全分析 | `pip install semgrep` |
| `npm audit` | Node.js 依赖安全 | 已内置 |
| `pip audit` | Python 依赖安全 | `pip install pip-audit` |

## 应急响应

### 如果密钥已经提交

```bash
# 1. 立即轮换密钥（最重要！）
# → 去对应平台（AWS Console / GitHub Settings / OpenAI Dashboard）重新生成

# 2. 从 Git 历史中清除
# 使用 BFG Repo-Cleaner
bfg --delete-files .env
bfg --replace-text passwords.txt

# 或使用 git filter-repo
git filter-repo --path .env --invert-paths

# 3. Force push 清理后的历史
git push --force-with-lease

# 4. 通知团队
# → 告知所有协作者拉取最新代码
```

### 密钥泄露检查清单

- [ ] 已轮换/废弃泄露的密钥
- [ ] 已从 Git 历史中清除
- [ ] 已添加到 `.gitignore`
- [ ] 已添加 pre-commit hook 防止再次发生
- [ ] 已检查是否有未授权访问
- [ ] 已通知相关团队成员
