# 技能系统完整参考

> 技能 (Skills) 是预定义的操作流程，封装了重复性任务的最佳实践。
> 激活后成为智能体的主要指令源，按步骤严格执行。

---

## 一、内置技能清单

### 1. PR 工作流技能
```yaml
名称: pr-workflow
触发: 需要创建、更新或管理 PR 时
步骤:
  1. 检查当前分支状态
  2. 运行 lint + typecheck
  3. 获取 PR 模板 (fetch_pr_template)
  4. 创建 PR (git_create_pr)
  5. 等待 CI (git_pr_checks)
  6. CI 失败则修复（最多 3 次）
  7. 通知用户 PR 链接 + 预览 URL
```

### 2. 仓库设置技能
```yaml
名称: repo-setup
触发: 需要设置/配置开发环境时
步骤:
  1. 读取 README.md, CONTRIBUTING.md, package.json/pyproject.toml
  2. 创建设置计划并发送给用户
  3. 安装依赖（按 README 指定工具）
  4. 运行构建
  5. 运行测试
  6. 启动 dev server 验证
  7. 如果有 .pre-commit-config.yaml → pre-commit install
  8. 建议环境蓝图 (update_environment_config)
```

### 3. 测试技能
```yaml
名称: testing
触发: 用户要求测试应用或验证功能时
步骤:
  1. 启动录屏 (recording_start)
  2. 标注 setup (annotate_recording type=setup)
  3. 启动应用/导航到目标页面
  4. 对每个测试用例:
     a. 标注 test_start
     b. 执行操作
     c. 检查结果
     d. 标注 assertion (passed/failed)
  5. 停止录屏 (recording_stop)
  6. 发送录屏给用户
```

### 4. 调试技能
```yaml
名称: debugging
触发: 需要诊断和修复运行时问题
步骤:
  1. 收集信息（错误信息、堆栈、日志）
  2. 形成假设（可能的原因列表）
  3. 验证假设（搜索代码、添加日志、运行测试）
  4. 定位根因
  5. 实现修复
  6. 验证修复（测试通过 + 手动验证）
```

### 5. 代码审查技能
```yaml
名称: code-review
触发: 需要审查代码或响应审查反馈
步骤:
  1. 读取 PR diff 和描述
  2. 理解变更意图
  3. 检查:
     - 代码正确性
     - 边界情况处理
     - 错误处理
     - 性能影响
     - 安全问题
     - 测试覆盖
  4. 撰写审查评论
  5. 如果是响应反馈: 用新 commit 修复
```

### 6. 部署技能
```yaml
名称: deployment
触发: 需要部署应用时
步骤:
  1. 确认部署目标（前端/后端/全栈）
  2. 检查部署配置是否存在
  3. 运行构建确保通过
  4. 执行部署命令
  5. 验证部署成功（检查 URL 或日志）
  6. 通知用户部署 URL
```

### 7. 子会话管理技能
```yaml
名称: child-sessions
触发: 任务可并行拆分时
步骤:
  1. 分析任务，拆分为独立子任务
  2. 为每个子任务创建 Devin 子会话
  3. 监控子会话进度
  4. 收集结果
  5. 合并/整合输出
注意: 子会话有独立 VM，不共享文件系统
```

### 8. 数据分析技能
```yaml
名称: data-analysis
触发: 需要分析数据、生成报告或可视化
步骤:
  1. 理解数据源（文件/数据库/API）
  2. 探索数据结构
  3. 编写分析代码（Python/SQL）
  4. 生成可视化（matplotlib/plotly）
  5. 总结发现
  6. 发送结果给用户
```

## 二、自定义技能开发

### 文件结构
```
.devin/skills/          # Devin 平台
.agents/skills/         # 通用
项目根/skills/          # 自定义位置
```

### SKILL.md 模板
```markdown
---
name: my-custom-skill
description: |
  当需要 [做某事] 时使用此技能。
  适用于 [什么场景]。
---

# 技能名称

## 前置条件

- [ ] 环境中已安装 X
- [ ] 有 Y 的访问权限
- [ ] Z 服务正在运行

## 步骤

### 1. 准备阶段
详细描述第一步...

```bash
# 具体命令
command --flag value
```

### 2. 执行阶段
详细描述第二步...

### 3. 验证阶段
如何确认执行成功...

## 常见问题

### Q: 如果 X 失败怎么办?
A: 尝试 Y，如果仍然失败，检查 Z。

## 注意事项

- 不要在生产环境执行 X
- 执行前确保 Y
```

## 三、技能激活与执行

### 激活方式
```yaml
# 手动激活
skill(command="invoke", skill="my-skill-name")

# 列出可用技能
skill(command="list", path="/path/to/project")

# 搜索技能
skill(command="search", path="/path", keywords=["deploy", "testing"])
```

### 执行规则
1. **严格按顺序** — 不跳步、不合并
2. **步骤失败时排障** — 不静默跳过
3. **技能是主要指令源** — 激活后优先遵循
4. **可选步骤标记** — 只有标注 optional 的才能跳
5. **完成后校验** — 对照技能检查每步是否执行

## 五、技能最佳实践

### 应该写成技能的
- 重复执行的部署流程
- 项目特有的测试方法
- 登录/认证流程 (Playwright 脚本)
- 数据迁移步骤
- 特定环境的调试方法

### 不应该写成技能的
- 一次性任务
- 过于通用的操作（已有工具覆盖）
- 包含密钥的步骤（用 ${SECRET_NAME} 引用）
- 特定 PR 的操作

### 技能维护
- 定期验证技能是否仍然有效
- 环境变更后更新相关技能
- 用 suggest_skill_pr 工具提交技能更新
- 技能文件随项目版本控制
